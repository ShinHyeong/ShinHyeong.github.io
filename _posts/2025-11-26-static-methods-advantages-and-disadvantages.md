# static 메소드의 장단점

| 항목 | 장점 (Advantages) | 단점 (Disadvantages) |
| --- | --- | --- |
| **호출 방식** | - **객체 생성 없이** 클래스 이름으로 바로 호출 가능. | - 객체 고유의 상태를 다룰 수 없음 (**인스턴스 변수 접근 불가**). |
| **메모리** | - **메모리 효율적:** 클래스가 로드될 때 메소드영역에 한 번만 할당되어 모든 객체가 공유함 → 인스턴스마다 **별도의 메모리 공간이 필요 x** | - **메모리 관리의 특수성:** 1. 일반적인 **GC대상 x** → 프로그램 종료 시까지 메모리에 남아있을 가능성이 높음. 2. 과도한 사용 시 모든 static 데이터가 메소드영역에 한꺼번에 로드되어 **프로그램 시작** 시 **메모리 부담**이 커질 수 있음. → 힙 영역을 통한 동적인 메모리 할당의 장점을 활용하기 어려워집니다. |
| **특성** | - 유틸리티성 기능 구현에 적합함. | - 다형성 활용 불가**:** **오버라이딩 지원x** - 객체지향의 장점(캡슐화, 상속, 다형성)을 온전히 활용하기 어려움. |
1. 가장 큰 장점은 **객체 생성 없이 바로 호출**할 수 있다는 점입니다.
    - 별도의 객체 생성 과정 없이 `클래스이름.메소드이름()`으로 즉시 접근할 수 있어서 유틸리티성 공통기능을 구현할 때 유용합니다.
    - **메모리 효율성:** 또, static 메소드는 클래스 로딩 시점에 메소드 영역에 딱 한 번만 로드됩니다. 여러 객체가 이 메소드를 공유해서 사용하기 때문에, 인스턴스마다 별도의 메모리 공간이 필요 없으므로  메모리를 효율적으로 사용하는데 큰 장점이 됩니다,
2. static 메소드의 단점은
    - 먼저, 메모리 관리 측면에서 한계가 있습니다. 만약 모든 멤버를 static으로만 만든다면, 프로그램 시작 시에 메소드 영역에 한꺼번에 로드되어서 **초기 메모리 부담**이 커질 수 있습니다.
    - 이렇게 되면 힙 영역을 통한 동적인 메모리 할당의 장점을 활용하기 어려워집니다.
    - 그리고, GC 대상이 아니기 때문에 프로그램 종료 시까지 메모리에 남아있을 수 있습니다.
    - 이외에도 ****static 메소드는 객체가 생성되어야만 존재하는 인스턴스 변수에는 접근할 수 없고, 오버라이딩을 구현할 수 없다는 단점이 있습니다. (컴파일 시점에 호출될 메소드가 결정되므로)

---

### +) 그러면 어떨 때 사용해야할까요?

static 메소드는 **객체의 상태(인스턴스 변수)와 무관하게 동작하는 공통 기능**이나, **유틸리티성 메소드**를 만들 때 사용하는 것이 적절하다고 생각합니다.
