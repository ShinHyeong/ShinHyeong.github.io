간단하게 말하자면 

- `==` 연산자 : 두 객체의 메모리 주소를 비교하는 연산자 (= 둘이 완전히 같은 객체인가?)
- `equals()` : 두 객체의 내용을 비교하는 연산자 (= 메모리 주소는 상관없고, 둘이 내용이 같나?)

# `==`연산자

- 두 객체의 ***메모리 주소*를 비교**하는 연산자
    - 좀더 자세히 말하자면, 기본타입 변수의 경우, 변수에 저장된 실제 값 비교함
    - 참조타입 변수의 경우, 힙 영역에 저장된 객체의 메모리주소 비교함
- 즉, 두 변수가 메모리상에서 **완전히 같은 객체**를 가리키는지 확인함 (동일성 비교)
- 쓰임 : 기본 타입 변수 비교 (primitive types)

```java
String str1 = new String("java");
String str2 = new String("java");

System.out.println(str1 == str2); // false

//다른 주소값으로 서로 다른 객체를 가르키고 있기 때문
```

# `equals()`

- 오버라이딩 해서 두 객체의 ***내용*이 같은지** 확인하기 위해 사용하는 연산자
    - Object 클래스에 정의된 기본 구현은 `==` 연산자와 동일하게 메모리 주소값을 비교함(=동일성)
        
        > "나는 가장 기본적인 주소 비교만 제공할 테니, 너희 클래스만의 특별한 '동등성' 기준이 필요하다면 직접 구현해라.”
        > 
        
        `Object`는 자바의 모든 클래스의 최상위 부모입니다. 하지만 `Object` 클래스 입장에서는 **나를 상속받을 하위 클래스들이 어떤 데이터를 가질지 전혀 알 수 없습니다.**
        
        - 어떤 클래스는 `이름`이 같을 때 같은 객체라고 판단할 수도 있고,
        - 어떤 클래스는 `고유 ID`가 같아야 같은 객체라고 할 수도 있습니다.
        - **따라서 최상위 클래스가 함부로 "이 값이 같으면 같은 객체다"라고 정의할 수 없습니다.**
        
        이 상황에서 모든 객체가 공통으로 가지고 있는 유일한 확실한 정보는 메모리 주소뿐입니다. 그래서 가장 보수적이고 확실한 기준인 '물리적 동일성(Identity)'을 기본값으로 선택한 것입니다.
        
        ```java
        public boolean equals(Object obj) {
            return (this == obj);
        }
        ```
        
    - 그러나 String, Integer 등 래퍼클래스의 경우, 이를 **오버라이딩(재정의)**하여 객체의 내용을 비교하는데 씀
- 두 객체의 내용만 같으면 메모리상 서로 다른 위치에 있어도 같다고 함 (동등성 비교)
- 쓰임 : `String, 'Integer' Wrapper 클래스 등 *객체의 내용을 비교해야할 때*

```java
String s3 = new String("java");
String s4 = new String("java");

System.out.println(s3.equals(s4)); // true

// 주소가 아닌 내용을 비교함
```
