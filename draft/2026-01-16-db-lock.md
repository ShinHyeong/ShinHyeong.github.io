# 락(Lock)

> 데이터에 대해 동시에 여러 작업이 수행되지 않도록 잠그는 메커니즘
> 
> 
> 데이터 접근을 **제어하여 충돌을 막는 기술**
> 

한 트랜잭션이 어떤 데이터를 수정하고 있는 동안,

다른 트랜잭션은 그 데이터를 **읽거나 바꾸지 못하도록 막는 것**이 락이야.

사용하는 이유 : 동시성 제어, 무결성 유지, 충돌 방지

---

## 🔐 1) 락의 종류

### 🔹 **공유 락 (Shared Lock, S Lock)**

- 데이터를 읽을 수는 있지만 **수정은 안 됨**
- 여러 트랜잭션이 동시에 공유 락을 걸 수 있음
    - 여러 트랜잭션이 **같은 데이터를 동시에 읽는 건 가능**
- 하지만 이 상태에서 **수정(UPDATE, DELETE)은 안 됨** → 수정하려면 배타 락 필요

```sql
📌 SELECT ... FOR SHARE (PostgreSQL 등)
```

---

### 🔹 **배타 락 (Exclusive Lock, X Lock)**

- 데이터를 **읽고 수정할 수 있는 권한**
- 동시에 한 트랜잭션만 걸 수 있음 (다른 트랜잭션은 대기)
    - 한 트랜잭션만 **읽기 + 쓰기 가능**, 나머지는 대기
    - 락이 걸린 동안 **다른 트랜잭션은 그 데이터에 접근 불가** (읽기도 불가능)
- 쓰기 작업(UPDATE, DELETE 등)은 항상 **배타 락을 획득**해야 함

```sql
📌 SELECT ... FOR UPDATE
```

---

### 🔹 **행 락 (Row-Level Lock)**

- 특정 **하나의 행(Row)만 잠금**
- 동시성 높고 효율적
- 대부분의 RDBMS(InnoDB, PostgreSQL 등)에서 지원

### 🔹 **테이블 락 (Table-Level Lock)**

- 테이블 전체 잠금
- 간단하지만 동시성이 낮음
- MyISAM(MySQL의 예전 엔진)에서는 기본 방식

### 🔹 **낙관적 락 (Optimistic Lock)**

- 충돌이 **잘 안 난다고 가정**
- 실제 수정 시점에 버전 확인 → 충돌 나면 **롤백**

```sql
UPDATE users SET name = '홍길동', version = version + 1
WHERE id = 1 AND version = 3;
```

- 💡 주로 버전 번호(version)나 **타임스탬프**로 구현

### 🔹 **비관적 락 (Pessimistic Lock)**

- 충돌이 **잘 날 거라고 가정**
- 데이터를 읽는 시점에 **미리 락을 걸어두고**, 다른 트랜잭션이 접근하지 못하게 함

```sql
SELECT * FROM users WHERE id = 1 FOR UPDATE;
```

### 🔹 **의도적 락 (Intent Lock)**

- 테이블 수준에서 락을 걸기 전,
    
    하위 단위에 락이 있다는 것을 **미리 표시**하는 메타 락
    
- **InnoDB가 내부적으로 사용** (사용자가 직접 쓰진 않음)

---

## 🔁 2) 트랜잭션과 락의 관계

- 트랜잭션은 락을 통해 **동시성 문제를 방지**
- 락은 트랜잭션이 끝날 때(`COMMIT` 또는 `ROLLBACK`)까지 유지됨
- `READ COMMITTED`, `REPEATABLE READ` 같은 **격리 수준에 따라 락 전략이 달라짐**

---

## 📦 3) 락의 범위

| 범위 | 설명 |
| --- | --- |
| **Row-Level Lock** | 특정 행(Row)만 잠금 (세밀하고 효율적) |
| **Table-Level Lock** | 전체 테이블 잠금 (간단하지만 동시성 낮음) |
| **Page-Level Lock** | 디스크 페이지 단위로 잠금 (DBMS 내부 사용) |

---

## ⚠️ 4) 락과 관련된 문제

### 🔹 **데드락(Deadlock)**

- 서로 락을 기다리며 **영원히 멈춰 있는 상태**
- DB는 이걸 감지해서 트랜잭션 중 하나를 자동으로 죽임

### 🔹 **락 경합(Lock Contention)**

- 여러 트랜잭션이 **동일한 자원을 동시에 잠그려다** 대기 상태가 많아지는 현상

---

## ✅ 5) SQL 예시

```sql
-- 공유 락: 읽기만 가능
SELECT * FROM accounts WHERE id = 1 FOR SHARE;

-- 배타 락: 읽고 수정 가능, 다른 트랜잭션은 못 건드림
SELECT * FROM accounts WHERE id = 1 FOR UPDATE;

```
