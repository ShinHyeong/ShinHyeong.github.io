# 트랜잭션 : 복잡한 연산 조합을 “하나의 단위”로 취급하는 논리적 단위

가장 대표적인 예시 A가 B에게 100원을 송금하는 “계좌 이체” 시나리오를 들어보겠습니다. 시스템은 다음과 같은 결과를 내야합니다.

- Step 1 : A의 계좌는 100원을 차감한다
- Step 2: B의 계좌에 100원을 증액한다

트랜잭션이란 DB의 상태를 변화시키기 위해 수행하는 “**작업의 논리적 단위**”를 의미합니다.

여러 개의 연산이 수행되더라도, 시스템은 이를 쪼갤 수 없는 “**하나의 작업**”처럼 묶습니다. 

아까 언급한 계좌이체 시나리오에서 트랜잭션은 Step1+Step2를 의미합니다.

# 트랜잭션 왜 사용하나? : All or Nothing으로 데이터의 일관성 보장

그런데 만약 A의 잔액 차감 단계(Step1)까지는 성공했는데, 갑자기 시스템 장애로 인해 B의 잔액 증액 단계(Step2)가 실패한다면 어떻게 될까요? 

A의 잔액은 줄어들었지만, B는 예정된 100원을 못 받게 되겠죠? 이처럼 돈은 사라지고 **데이터의 불일치**가 발생합니다.

왜 이런 일이 발생했을까요? 여러 개의 연산이 수행하더라도 이를 하나의 작업처럼 취급해야하는데, 그렇지 않고 부분적인 성공을 허용했기 때문입니다.

이를 위해 트랜잭션이라는 개념이 등장하게 됩니다.

부분적인 성공을 허용하지 않고, 전부 성공하거나 전부 실패하게 함으로써 **데이터의 일관성을 보장**하는 것이 목적입니다. 

다수의 사용자가 동시에 접근하고, 예기치 못한 서버 장애가 빈번한 백엔드 환경에서 트랜잭션은 **데이터의 신뢰성**을 지켜줍니다.

트랜잭션은 복잡한 작업을 완전한 “**하나의 단위**”로 묶어 시스템의 불확실성에서도 데이터의 완전함을 보장합니다.
