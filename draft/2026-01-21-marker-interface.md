# 마커 인터페이스 : 메소드가 없는 인터페이스

메소드/필드가 전혀 선언되지 않은 빈 인터페이스

**목적 : 표시(Marking)** - 객체에게 기능을 강제하는 것이 아니라, 해당 클래스가 **특정 속성을 가지고 있음**을 “**표시**”하기 위해서 존재함

즉, 클래스에게 어떤 행동(Behavior)을 정의하는 게 아니라, **정체성(Identity)을 부여**하기 위해 존재함. JVM이 이를 보고 특정 동작을 수행하게 함.

어찌보면 어노테이션과도 비슷하게 생각할 수 있지만, 어노테이션은 런타임에 리플렉션을 통해 확인해야하는 반면, 마커 인터페이스는 **컴파일러 수준**에서 **타입 안전성**을 **보장**받고 싶을 때 사용. 

```java
public interface Serializable{ } // 아무것도 선언하지 않음
```

## 비유 : 도서관의 분류 스티커

스티커 자체에는 글자가 쓰여있지않지만, 이 스터커가 붙으면 “문학 장르”임이 증명됨

→ 사서(JVM)은 책 내용을 다 읽지 않아도, 스티커만 보고 이 책의 분류와 처리방식을 즉시 결정할 수 있음

즉, 마커 인터페이스는 클래스에 붙이는 분류 스티커와 같음

## 자바 표준 라이브러리 속 마커 인터페이스 : Serializable, Cloneable

자바는 런타임 동작를 제어하고 권한을 부여하기 위해 오래전부터 이 마커 인터페이스를 사용해왔음

- Serializable : **JVM**은 “이 객체는 **직렬화**할 수 있는 객체구나”라고 **판단**하여 직렬화 처리를 허용함.
- Cloneable : JVM은 “이 객체는 clone()로 복제될 수 있는 객체구나”라고 판단하여 얕은복사를 허용함

# 마커 인터페이스의 장점 : 타입체크, 다형성 활용

1. 컴파일 타임에 타입 체크 가능

**특정 타입만 매개변수로 받고 싶을 때** 마커 인터페이스를 타입을 지정함으로써 런타임 에러를 사전에 방지할 수 있음. **`instanceof`** 연산자로 해당 클래스가 특정 속성 가지는지 체크함.

1. 다형성 활용

해당 마커 인터페이스를 구현한 모든 클래스를 하나의 타입으로 묶어 처리할 수 있어 설계의 유연성이 높아짐
