# 파티셔닝 (Partitioning)

**대용량 데이터를 효율적으로 관리하고 성능을 향상시키기 위한 데이터베이스 기술**

> 하나의 큰 테이블을 내부적으로 여러 개의 작은 단위(파티션)로 나누어 저장하는 것 → 쿼리 성능과 유지관리 효율을 높임
> 
- 사용자는 여전히 **하나의 테이블처럼 조회**
- 실제로는 **백엔드에서 여러 조각으로 분리되어 있음**
- 쿼리 시 해당 파티션만 조회하게 되어 **성능 향상**

## 📘 1) 왜 파티셔닝을 사용할까? (목적)

- 💨 쿼리 성능 향상 - **대용량 테이블의 조회 성능 향상** (파티션 프루닝 가능)
- 💾 관리 용이 - 파티션별 **백업/삭제/보관 단위로 나누기 쉬움**
- 📊 **기간별/범주별 데이터 관리 최적화**

## 📂 2) 파티셔닝의 종류

| 유형 | 설명 |
| --- | --- |
| **Range 파티셔닝** | 특정 범위 기준으로 분리 (예: 날짜, 숫자) |
| **List 파티셔닝** | 특정 값 목록 기준으로 분리 (예: 지역, 등급) |
| **Hash 파티셔닝** | 해시 함수를 이용해 고르게 분산 |
| **Composite 파티셔닝** | 위 방식들을 조합하여 사용 (예: Range + Hash) |

### 📌 예: Range 파티셔닝 (MySQL 기준)

```sql
CREATE TABLE orders (
    id INT,
    order_date DATE
)
PARTITION BY RANGE (YEAR(order_date)) (
    PARTITION p2023 VALUES LESS THAN (2024),
    PARTITION p2024 VALUES LESS THAN (2025)
);

```

- 2023년 주문은 `p2023` 파티션,
- 2024년 주문은 `p2024` 파티션에 저장됨

## 3) 파티셔닝의 장단점

### ✅ 파티셔닝의 장점

- 🚀 **쿼리 성능 향상** (필요한 파티션만 조회)
- 📦 **테이블 관리 용이** (예: 오래된 파티션만 삭제)
- 🔄 **병렬 처리 가능** (각 파티션 단위로 처리)

### ❌ 파티셔닝의 단점

- ❗ **설계 복잡성 증가**
- ❌ 인덱스, 외래키 등 일부 제한 사항 있음
- ❌ 잘못 설계하면 오히려 성능 저하
- 💡 DBMS마다 파티셔닝 지원 방식이 다름 (MySQL, PostgreSQL, Oracle 등)
